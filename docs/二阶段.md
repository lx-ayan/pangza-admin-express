### pangza-admin-express 二阶段开发

二阶段我们针对类来进行开发，我们针对类 + 装饰器进行开发，所以二阶段主要是搭类+装饰器架构。主要针对 Spring Boot 相似即可。

> 装饰器参数、用法与实现原理见：[docs/README.md](./README.md)（按模块拆分在 `docs/decorators/`）。

架构代码统一放在 `src/framework`（Application / Auth / ORM / Service / Json / Exception / Validate / config / types / utils 等），业务放在 `src/business`。可通过 `Application.scan(...)` 指定扫描目录，未调用时默认扫描 `src/business`，自动注册带 `@Controller` 的类。

#### @Controller 注解

类装饰器，作用于类上，可以传递一个字符串，传递这个字符串后，这个类中的所有接口都要以这个字符串为开头。

#### @GetMapping 注解

函数装饰器，在 Controller 标注的类中使用，传递一个字符串表示接口。GetMapping 标注是一个 get 接口。

#### @PostMapping 注解

函数装饰器，在 Controller 标注的类中使用，传递一个字符串表示接口。PostMapping 标注是一个 post 接口。

#### @PutMapping 注解

函数装饰器，在 Controller 标注的类中使用，传递一个字符串表示接口。PutMapping 标注是一个 put 接口。

#### @DeleteMapping 注解

函数装饰器，在 Controller 标注的类中使用，传递一个字符串表示接口。DeleteMapping 标注是一个 delete 接口。

#### 权限校验

权限校验使用函数装饰器：

| 装饰器 | 说明 |
|--------|------|
| `@AuthCheckLogin()` | 必须登录 |
| `@AuthCheckRole(...roles)` | 角色校验，传入角色数组 |
| `@AuthCheckPermission(...permissions)` | 权限码校验，传入权限数组 |
| `@AuthIgnore()` | 本接口跳过鉴权（白名单） |

校验模式（角色 / 权限数组内部）：

- **OR**（默认）：数组中只要满足一个即可通过
- **AND**：必须全部满足才通过，有一个不满足则不通过

可在 Auth 模块配置里设置全局默认模式，也可在装饰器上按接口覆盖，例如：

```ts
@AuthCheckPermission(["sys:user:add", "sys:user:edit"], { mode: "AND" })
```

#### 参数解析装饰器

这些都是参数装饰器。没有标注就还是传入 `request`，让用户自己去拿。

| 装饰器 | 说明 |
|--------|------|
| `@RequestQuery()` | 取 query 参数 |
| `@RequestBody()` | 取 body |
| `@RequestPath(index?: number)` | 取 path 参数；可指定下标 |
| `@RequestHeader()` | 取请求头 |
| `@RequestCookie()` | 取 Cookie |

#### 数据访问层

`@Mapper(table)` 表示这个类是一个 mapper 类，有着 BaseMapper 的方法。

`@Service(mapper)` 注入一些方法 insert、delete、… 像 MyBatis-Plus 那样。我们这个简单一点。

`@Component(name)` 表示一个组件，把它自动注入到容器中。

`@Resource(name)` 表示从容器中获取，然后自动实例出来。使用的话就通过 `this.xxx` 直接使用。

BaseMapper 除常规 CRUD 外，增加批量方法，避免用户循环多次执行 SQL：

- `saveBatch(list)`：批量插入
- `deleteByIds(ids)`：按主键批量删除（配合逻辑删除配置时走逻辑删）

#### ORM 第二期开发

1. 增加逻辑删除配置，配置删除值是多少，然后配置是什么字段，功能和 MyBatis-Plus 一样。然后还可以增加创建拦截、修改拦截，可以默认操作一些数据，比如 `createTime`、`updateTime` 在创建或更新时自动填充。还有乐观锁机制，也加一下。逻辑删除、乐观锁让用户配置是否开启。

2. 封装 `@Select`、`@Insert`、`@Update`、`@Delete` 等装饰器。`#{}` 参数绑定（预编译 `?`），`${}` 字符串替换（同 MyBatis；仅用于可信内容）。可用 `@Param("x")` 命名参数。

3. 封装 `@TableName`、`@TableId`、`@TableField`，与 MyBatis-Plus 基本保持一致。

   `@TableField` 自定义：`insertFill` 可传函数（返回值）或直接填值，插入时默认填充；`updateFill` 同理（更新时填充）。

4. 字段映射：把 SQL 查询结果映射到实体字段上。比如 `children` 字段打上 `@Select` 装饰器，把查询出来的结果放进这个字段；再比如 menu 类里有 `roleName`，给 `roleName` 打上装饰器：

   `select name from role where id = (select roleId from menu_role where menu_id = ???)`

5. 增加 `saveBatch`、`deleteByIds`，避免用户使用循环多次执行 SQL。

6. 增加 `@Transactional` 装饰器（事务），可标注在类或函数上；方法内多步写库失败时回滚，用法接近 Spring / MyBatis-Plus。底层基于连接事务（`BEGIN` / `COMMIT` / `ROLLBACK`），支持嵌套时按统一策略处理（如加入外层事务）。

7. 对齐 Java `@TableSearch`：`OperTypeEnum` + `getQueryWrapper` / `getQueryWrapperAndPage(form, FormClass, …)`（JSON form 须传 DTO 类读元数据）；`QueryWrapper` 补 `likeLeft` / `likeRight`。

#### 其他开发

1. 做一个 JSON format 装饰器，可以固定返回格式，比如装饰在日期类型的数据上可以自定义返回给前端的格式。然后做一个全局返回处理，类似于 Spring Boot 的 `ObjectMapper`。

2. 我们还没有错误处理，增加一个全局错误处理机制，像 Spring Boot 那样自定义全局处理（`@ControllerAdvice` + `@ExceptionHandler`）。

3. 使用 validator 这类能力，封装一些函数，校验参数。支持函数式和装饰器调用。使用 `@Validate` 或 `validateHandler(validatorParam)` 校验，也参考 Spring Boot。先处理非空、最大值、最小值、邮箱、手机号等；也可以用户使用注解传一个函数自己定制规则（如 `@Custom`）。

4. 封装一个函数做参数转化：使用后返回目标对象。比如源对象 `{ username: 'admin', password: 'asdasd', tags: [] }`，目标对象 `User { username, password }`，转换后得出 `{ username, password }`（`convert`）。

5. `@JsonInclude` 也封装一下（空值 / 空串等按策略不输出）。

#### Auth 模块

Auth 模块 Token 可以自定义：登录配置、过期时间、token 风格、多设备等（已引入 `jsonwebtoken`）。

主要配置项：

| 配置 | 说明 |
|------|------|
| `tokenName` | Token 名称（请求头 / Cookie） |
| `timeout` | 过期时间 |
| `activityTimeout` | 活跃超时（多久无操作失效） |
| `tokenStyle` | Token 风格：`uuid` / `jwt` 等 |
| `jwtSecret` | JWT 密钥（`tokenStyle=jwt` 时） |
| `allowConcurrentLogin` | 是否允许多端同时登录 |
| `isShare` | 是否共享同一 Token |

校验权限模式：支持 **OR** / **AND**。

- **OR**（默认）：只要满足一个角色或权限即可通过
- **AND**：全部满足才通过，有一个不满足都不通过

可在 Auth 初始化时配置全局默认，并在 `@AuthCheckRole` / `@AuthCheckPermission` 上按接口覆盖。
